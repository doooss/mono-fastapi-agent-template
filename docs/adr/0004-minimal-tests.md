# ADR-0004 — 테스트는 버그를 잡을 수 있을 때만

- **Status**: Accepted
- **Date**: 2026-11-21
- **Refs**: 261121_001_template-bootstrap
- **Supersedes**: —

## Context

mock 이 mock 값을 돌려주는지만 보는 테스트(DB mock, SDK 클라이언트 mock)는 유지 비용만 들고 실제 버그를 잡지 못한다.
에이전트 코드는 모델 호출이 끼어 있어 "응답을 흉내 내는 mock" 테스트로 흐르기 쉽다.

## Decision

- unit = 분기 있는 순수 로직만 — 이벤트 번역기(실제 SDK 타입 입력), 도구 실행기, 집계, 변환.
- e2e = 실제 HTTP 설정 + 실제 SQLite 파일 + Alembic 마이그레이션 + `ScriptedBackend` (실제 백엔드와 같은 `RunContext` 경로, 모델 호출 없음).
- 쓰지 않는다: DB mock · SDK 클라이언트 mock · 실제 모델 호출 · prompt 문구 단언 · 프레임워크 동작 재확인.

## Alternatives

| 대안 | 기각 이유 |
| --- | --- |
| SDK 응답을 mock 한 백엔드 테스트 | mock 이 가정한 응답 모양만 검증 — 번역기를 떼어 실제 타입으로 테스트하는 쪽이 같은 버그를 더 싸게 잡는다 |
| 실제 모델을 부르는 통합 테스트 | CI 에 키 · 비용 · 비결정성. 수동 스모크로 둔다 |

## Consequences

- **긍정**: 테스트가 실패하면 실제 결함이다. CI 에 secret 이 필요 없다.
- **부정**: 백엔드 루프 자체(네트워크 · 재시도 · 스트림 수명)는 자동 테스트 밖 — 실제 키로 수동 스모크가 필요하다.
- **후속**: 백엔드별 수동 스모크 절차를 사양 `## 알려진 한계` 에 둔다.
