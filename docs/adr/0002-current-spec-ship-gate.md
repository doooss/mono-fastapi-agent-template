# ADR-0002 — 현재 사양 중심 출고 게이트

- **Status**: Accepted
- **Date**: 2026-11-21
- **Refs**: 261121_001_template-bootstrap
- **Supersedes**: —

## Context

작업 기록에 과정만 쌓이면 지금 동작이 흩어지고, task 종료를 배포 확인에 묶으면 task 가 오래 열린다.
nestjs-template 이 같은 문제를 출고 게이트로 풀었고, 이 템플릿도 같은 체계를 쓴다.

## Decision

- task 는 `agent-work/` (pending → progress → done). **done = 출고 게이트 통과 + 커밋** — 로컬 검증 → 적대적 리뷰(필수, 새 컨텍스트) → 기록 압축(4 섹션) → ADR → 현재 사양(`docs/specs/`) 덮어쓰기 → 한 커밋.
- 사양은 개체(모듈 · 패키지 · 흐름) 단위로 **현재만** 쓴다. 이력은 git · task · ADR.
- CI 커밋 감사가 출고 결과물의 존재 · 형식을 검사한다. 내용이 맞는지는 적대적 리뷰 몫.

## Alternatives

| 대안 | 기각 이유 |
| --- | --- |
| 변경 로그 · 과정 로그 문서 | 지금 동작을 알려면 전부 읽어야 한다 |
| 배포 확인까지 task 를 연다 | task 가 릴리스 주기에 묶여 오래 열린다 — 배포는 파이프라인 몫 |
| 리뷰 선택 | 사소한 변경에서 놓친 경계가 사양에 남지 않는다 |

## Consequences

- **긍정**: `docs/specs/` 만 읽으면 지금 동작을 안다. 에이전트 이벤트 계약 같은 횡단 규약이 한 문서에 고정된다.
- **부정**: 작은 변경에도 리뷰 1 round 와 사양 갱신 비용.
- **후속**: 없음.
